## 5. モデル間の判断が分かれた関数

### isStringRecord — 5/6 モデルが FAIL、gpt-5.2-codex だけ PASS

gpt-5.2-codex は「オブジェクトで非 null で非配列であれば Record<string, T> と見なせる」と判断し PASS 95。
他 5 モデルは「値が TSchema 型かの検証が不足」で FAIL。gpt-5.2-codex の判定は甘い。

### buildWelcomeMessage — 4 モデルが FAIL、gpt-4.1 だけ PASS 100

gpt-4.1 は「引数・戻り値の型は正しく、副作用もない」と判断し PASS。
他 4 モデルは「welcome と名乗りつつ premium 系関数を呼ぶ名前と実装の不整合」で FAIL。
gpt-4.1 は名前と意図の乖離を検出できない。

### getUserProfile — haiku-4-5 だけが FAIL

5 モデルが PASS (72-96) とした中、haiku だけが `void id;` によるパラメータ無視を検出し FAIL 10。
これは最も深刻なバグだが、他モデルは「関数としては型が正しい」と浅い分析で通している。

## 7. 結論

**haiku-4-5 が最もコスパが良い。** 唯一全バグを検出し、$1.06 は gpt-4.1 ($1.31) より安い。

CI では **gpt-4.1 で高速スクリーニング → haiku-4-5 で精密チェック** の 2 段階が有効。
gpt-4.1 は 89 秒で終わり誤検出がないため PR ブロッカーに適し、
haiku は見逃しを拾う第 2 パスとして機能する。

## 注意事項

- gpt-4.1 は `github-copilot/gpt-4.1` として GitHub Copilot API 経由。
  サブスクリプション利用時は per-token 課金と異なる可能性がある。
- Anthropic モデルは v1 ログ（SDK `costUSD` 報告値）を使用。
- OpenAI 系のコストは手計算。cache read の 50% 割引を適用。
- gpt-5-nano は 600s timeout で 23/27 のみ完了。27 scope 按分で ~$0.08。
- codex-mini-latest は全リクエストで空レスポンスを返し完全に動作せず。
- サンプルの意図的バグは 3 件のみ。より大きなサンプルでの検証が必要。
