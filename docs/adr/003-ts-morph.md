# ADR-003: ASTパーサーの統一（TypeScript含む全言語）

**日付:** 2025-03  
**ステータス:** 決定（ADR-003初版を更新）

### 背景

TypeScript専用のASTおよびd.ts取得にts-morphの採用を検討していたが、方針を見直した。

### 議論

型解決が必要かどうかを検討した結果、**そもそも型解決という問題設定自体が不要**という結論に至った。

codepolicyはLLMにコードを渡して判断させるツールであり、静的解析ツールではない。人間のレビュアーがコードを読んで文脈から判断するのと同様に、LLMもテキストとしてのコードから判断できる。型が完全に解決されていなくても、関数本体・型アノテーション・同ファイルのinterface定義というテキストレベルのコンテキストがあれば十分である。

この考え方はTypeScriptに限らず全言語に共通して適用できる。

### 決定

**全言語のAST取得をtree-sitterに統一する。ts-morphは採用しない。**

### 理由

- 型解決という問題設定自体がcodepolicyには不要
- tree-sitter一本で全言語を統一的に扱えるため、extractorの実装・メンテナンスコストが下がる
- MVPとして最もシンプルな構成になる
